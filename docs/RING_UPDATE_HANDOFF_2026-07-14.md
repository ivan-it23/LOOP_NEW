# Передача контекста новой сессии: текущее состояние LOOP_NEXT

Дата исходной фиксации: 2026-07-14

Актуализировано: 2026-07-15

Этот документ является основной точкой входа для новой сессии. Он заменяет необходимость перечитывать историю чата. Полная архитектура и функциональность описаны в `docs\LOOP_NEXT_DOCUMENTATION.md`, а выпуск и автообновление — в `installer\README.md`.

## 1. Состояние проекта на момент передачи

- Актуальное приложение: `Кольца 1.0.5`, WinUI 3 / C# / .NET 10, unpackaged x64.
- Текущий `HEAD`: `2e8bf090` — исправление таблицы параметров кольца для трёхпередатчикового прибора.
- Коммит `6d136952` содержит полностью интегрированную логику новой прошивки кольца.
- Миграция из `LOOP_NEW` завершена; старый проект остаётся источником проверенного математического и последовательного поведения.
- Поддерживаются приборы `Автономный` 5 Tx, `LWD` 3/4/5 Tx и `Картограф_Режим_LWD_4tx`.
- Поддерживаются legacy- и extended-варианты протокола кольца, безопасное чтение/запись рабочих ячеек, AUTO, ручной проход, локальный воздух, расчёт ёмкостей и RTF-рапорт.
- Реальная поверка через Bluetooth после повторного расчёта ёмкостей дала хорошие значения таблицы; оператор подтвердил нормальную работу приложения в этой конфигурации.
- Исторические кабельные испытания показывали быстрые изменения отклика, `selection_dropped` и `no_physical_response`. Эти сессии сохраняются как доказательство транспортной/аппаратной нестабильности, но критические числа больше не считаются воспроизводимым дефектом математики приложения.
- Для приборов с 3 Tx строка сопротивлений больше не сокращается до шести полей: физические `R1..R8` отображаются всегда, а все строки расчёта сохраняют фиксированную ширину.

## 2. Неподлежащие случайному изменению контракты

### 2.1. Измерительный путь

Активный live-путь:

```text
GP_TOOL_DATA.DELTA_PH
-> NormalizePhase
-> знак по Rx_Position
-> локальный AIR
-> corrected phase
-> LoopResistivity.RoDfi
-> фазовый процент в таблице R1..R8
```

`phase_smt`, `rho_smt`, `GetPhaseSmt` и `GetAirSmt` перенесены, но не являются основным live-путём. Значение УЭС `7200` является fallback невозможности подобрать физическое значение, а не нормальным результатом.

### 2.2. Локальный воздух

- До AUTO или ручного прохода локальный воздух обязателен.
- При подключённом кольце сначала подтверждаются `RES 0` и `CAP 0`.
- После подтверждения пропускаются стабилизационные кадры и набирается выбранное число образцов.
- В текущем измерении baseline вычитается напрямую; повторной нормализации после вычитания нет.

### 2.3. AUTO и ручной проход

- В экспресс-режиме `R1` и `R2` проходят каждую логическую ёмкость отдельно.
- Только `R3..R8` используют две групповые точки по частотам.
- Для 5 Tx полный проход `R1/R2`: `CAP 1..10`; групповые точки `R3..R8`: `CAP 1` и `CAP 6`.
- Для 4 Tx полный проход `R1/R2`: логические `CAP 1..8`; групповые точки: `CAP 1` и логический `CAP 5`.
- Приложение не добавляет собственный сдвиг 4 Tx. Физический переход `CAP 5..8 -> 6..9` выполняет прошивка кольца.
- Новая точка начинает собирать кадры только после подтверждения обеих команд `RES/CAP`; затем пропускаются `5` кадров и выполняется выбранное усреднение.
- Ячейки `R1..R8` на главной вкладке содержат процент фазового отклонения, а не процент отклонения УЭС.

### 2.4. Память и таблица поверки кольца

- Физическая структура кольца всегда содержит восемь сопротивлений `R1..R8`.
- Строка `R, ohm` всегда имеет восемь полей независимо от числа передатчиков.
- Строки `C_req`, `RE_calc` и `Re meas` содержат 6, 8 или 10 рабочих значений для 3, 4 или 5 Tx.
- Все строки расположены на фиксированной десятипозиционной сетке; пустые позиции не растягивают рабочие поля.
- Legacy-профиль имеет 10 ячеек, extended-профиль — 32.
- Расчёт и штатная запись используют только `Z0..Z9`; `Z10..Z31` можно читать для диагностики, но UI не должен их перезаписывать.
- После `ZWRITE` выполняется обратный `ZREAD`; успех показывается только после совпадения записанных значений.
- Положительные `Re meas`, считанные из кольца или введённые пользователем, не заменяются расчётными значениями. `RE_calc` подставляется только в пустые/нулевые позиции.

## 4. Фактический контракт прошивки `zbox4`

Первичный код прошивки находится в `zbox4\Core\Src\main.c` и `zbox4\Core\Src\uart.c`.

Подтверждено исходниками:

- STM32F030, два интерфейса `9600` бод: `USART1` для RS-485 и `USART2` для Bluetooth.
- Обе ветки имеют независимые буферы и поддерживают `RES`, `CAP`, `ZREAD`, `ZWRITE`, `ZERASE`.
- `SetR` и `SetC` сначала отключают все реле соответствующей группы, затем включают только выбранное.
- При `NUMZONDES == 4` прошивка сама сдвигает логические ёмкости больше `4` на одну физическую позицию.
- В предоставленном `main.c` установлено `NUMZONDES 5`; для 4 Tx используется другая сборка/define.
- Сервисная функция `CycleC` выполняет встроенную последовательность `R/C`, но вызывается только обработчиком физической кнопки. Автоматического фонового перебора ёмкостей в коде нет.

Обнаружено несовпадение протокола подписи:

| Сторона | Чтение | Запись | Ответ чтения |
|---|---|---|---|
| `LOOP_NEXT` и `zbox3.docx` | `SGNREAD` | `SGNWRITE` | `SGN=<uint32>` |
| RS-485 в `zbox4` | `SGREAD` | `SGWRITE` | `SG=<uint32>` |
| Bluetooth в `zbox4` | не реализовано | не реализовано | `Unknown command!` |

Следствие: Bluetooth может исправно выполнять поверку через рабочие `RES/CAP/Z0..Z9`, но приложение классифицирует этот путь как legacy. Расширенный профиль 32 ячеек по Bluetooth нельзя считать подтверждённым. Менять приложение под `SGREAD/SG=` без согласования с разработчиком кольца нельзя, поскольку документированный и уже поддержанный контракт использует `SGN`.

## 5. Реальные испытания и интерпретация

Полезные исторические сессии в `src\LoopDeviceLog.txt`:

- `20260713-155721191-P8236` — прежняя ошибочная группировка `R1/R2` по пять каналов;
- `20260713-161815348-P40488` — после исправления `R1` идёт по одному каналу, но значения оставались критическими;
- `20260714-134148683-P23144` — диагностика фиксировала удерживаемые точки, включая последовательность `R1/C1..C9`;
- `20260714-141811271-P3732` — для части точек зафиксирован `selection_dropped` после подтверждённой команды;
- `20260714-144734343-P16468` — для ряда точек зафиксирован `no_physical_response`.

После этих испытаний оператор подключил кольцо через Bluetooth, заново рассчитал/записал ёмкости и получил хорошие значения процентов в таблице. Это текущий положительный аппаратный результат. Старые критические сессии не следует использовать как доказательство ошибки формулы без свежего повторения проблемы.

Не подтверждено одной полной тестовой матрицей:

- полный AUTO всех `R1..R8` для каждой конфигурации 3/4/5 Tx;
- физический сдвиг 4 Tx на конкретной прошивке кольца;
- одинаковая стабильность RS-485/USB и Bluetooth;
- точная причина различия результатов между кабельным и Bluetooth-подключением;
- расширенная signature/32-cell идентификация по Bluetooth;
- публикация `1.0.5` на сервер автообновления.

## 8. Как начинать следующую сессию

1. Прочитать этот документ.
2. При необходимости открыть полную архитектуру в `docs\LOOP_NEXT_DOCUMENTATION.md`.
3. Выполнить `git status --short` и сохранить все перечисленные release/doc-изменения.
4. Продолжать с новой задачи пользователя; не возвращаться к уже исправленным AUTO, фиксированным восьми сопротивлениям или старой группировке без новых доказательств.
5. При повторении числовой проблемы использовать только свежую `session` из `src\LoopDeviceLog.txt` и связывать `RING_COM`, `RING_MEASUREMENT`, `RING_FRAME`, `RING_FIRMWARE_DIAG` и `RING_CELL` по одному `run/point`.
6. Не менять фазовую математику, значения `Re meas`, программный 4 Tx-сдвиг или границу записи `Z0..Z9` до локализации конкретного расхождения.
7. Если следующая задача — публикация релиза, загрузить два файла на сервер и отдельно проверить URL версии и установщика.
